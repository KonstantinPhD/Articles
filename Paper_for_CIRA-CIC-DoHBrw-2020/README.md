Репозиторий содержит код и анализ для научной работы **"Сжатие признакового пространства в задачах обнаружения нарушений политики сетевой безопасности"**. Основная цель — исследовать методы сокращения количества признаков для обнаружения DNS-over-HTTPS (DoH) трафика, с фокусом на эффективность и пригодность моделей для работы на периферийных устройствах с ограниченными ресурсами.

### 📖 Основная идея

Современные модели машинного обучения для обнаружения сетевых атак часто требуют значительных вычислительных ресурсов, что делает их непригодными для развертывания на периферийных устройствах (например, в гетерогенных телекоммуникационных сетях, IoT и т.д.). В данной работе исследуется, как **редукция (сжатие) признакового пространства** может решить эту проблему. Основная гипотеза: использование меньшего, но наиболее информативного набора признаков позволяет сохранить точность обнаружения на высоком уровне, одновременно значительно снижая вычислительную сложность и время обработки.

### 🎯 Цели и задачи

1.  **Исследовать зависимость точности** модели Random Forest от количества топ-важных признаков.
2.  **Сравнить эффективность** двух критериев для оценки важности признаков: энтропии (информационный выигрыш) и примеси Джини (Gini importance).
3.  **Оценить производительность** (время обучения) в зависимости от размера используемого набора признаков.
4.  **Рассчитать информативность** признаков с помощью дивергенции Джеффриса (симметричной меры различия между двумя распределениями).
5.  **Провести комплексный анализ** метрик классификации (F1-Score, Precision, Recall) для выбора оптимального набора признаков.

### 🧠 Теоретическая база

В работе используются следующие математические подходы:

1.  **Дивергенция Джеффриса (Jeffreys Divergence)**: Симметричная мера для ранжирования признаков, вычисляемая для двух одномерных нормальных распределений (классов) по формуле:
    `DJ = ½ * [ (μ₁ - μ₂)²/σ₁² + (μ₁ - μ₂)²/σ₂² ] + ½ * [ σ₁²/σ₂² + σ₂²/σ₁² - 2 ]`
    Позволяет оценить, насколько хорошо каждый признак разделяет два класса (DoH и NonDoH).

2.  **Random Forest**: Используется как основной классификатор. Feature importance рассчитывается по двум критериям:
    *   **Энтропия (Entropy)**: Измеряет информационный выигрыш от использования признака.
    *   **Джини (Gini)**: Измеряет снижение примеси.

### 📊 Набор данных

Для анализа использован датасет **CIRA-CIC-DoHBrw-2020** (доступен по [ссылке](https://www.unb.ca/cic/datasets/dohbrw-2020.html)). Датасет содержит сетевой трафик и размечен на два основных класса:
*   **DoH (DNS-over-HTTPS)**: 600,364 образцов.
*   **NonDoH (обычный DNS-трафик)**: 214,929 образцов.
*   **Всего признаков**: 29 (`Duration`, `FlowBytesSent`, `PacketLengthMean` и др.).

### 📈 Ключевые результаты

1.  **Высокая корреляция критериев**: Коэффициент корреляции Спирмена между важностями признаков, вычисленными по энтропии и Джини, составил **0.961**, что говорит об их взаимозаменяемости в этой задаче.

2.  **Выдающийся признак**: Признак **`PacketLengthMode`** оказался доминирующим по всем метрикам, его вклад в модель кратно превышает вклад остальных.

3.  **Эффективное сжатие**:
    *   Уже при использовании **всего 5 топ-важных признаков** удается достичь точности (Accuracy) > **99.6%** и F1-меры > **99.6%**.
    *   При 1 признаке точность все еще высока — **~98%**.
    *   Дальнейшее добавление признаков (более 15) дает лишь незначительный прирост точности (менее 0.05%), но значительно увеличивает **время обучения**.

4.  **Производительность**: Время обучения растет практически линейно с добавлением новых признаков, что подтверждает необходимость сжатия для ресурсо-ограниченных устройств.

💡 Выводы и практическое применение
Сжатие признакового пространства более чем на 40% (использование топ-15 признаков вместо всех 29) не приводит к потере точности, но значительно ускоряет работу модели.

Это делает разработанный подход идеально подходящим для внедрения на периферийных устройствах, таких как маршрутизаторы, точки доступа, умные датчики и другие устройства с ограниченными вычислительными ресурсами.

Обнаружение DoH трафика может быть эффективно реализовано в реальном времени с минимальной задержкой, что критично для систем информационной безопасности.
